## Unsupported Behavior

Near-domain unsupported queries had substantially higher dense top-1 cosine scores than clearly out-of-scope unsupported queries:

- Near-domain dense top-1 score mean: about 0.6989
- Out-of-scope dense top-1 score mean: about 0.5121

This means dense cosine alone separates clearly out-of-scope questions more easily than near-domain unsupported questions.

Hybrid RRF scores and margins were much less separable:

- Near-domain hybrid rank-1 score mean: about 0.0317
- Out-of-scope hybrid rank-1 score mean: about 0.0301
- Near-domain hybrid rank-1/rank-2 margin mean: about 0.0016
- Out-of-scope hybrid rank-1/rank-2 margin mean: about 0.0019

Near-domain unsupported false accepts are therefore the central calibration risk. Rules that rely mainly on hybrid RRF margin or multiple high-ranking chunks accept many unsupported questions.

- `DENSE_SCORE_GE_0.75` is the strictest of the inspected rules: it produced no unsupported false accepts in the scope view, but it rejected 11 supported queries and retained only 43.75% coverage.

- Dense/hybrid agreement improves unsupported abstention compared with hybrid-only signals, but it rejects many otherwise safe supported queries.
- Hybrid RRF margin and chunk-support rules alone are weak abstention signals for this corpus because they accept many unsupported questions, including clearly out-of-scope cases.

## Major Failure Patterns

- `CAL031` remains the main supported-query safety failure. The expected document `DOC009` ranked 11 under Hybrid RRF, so accepting this query would be unsafe for both Top-3 and Top-5 answer contexts.
- Near-domain unsupported queries with BTP vocabulary are often retrieved with high dense cosine scores. This creates false accepts for threshold rules at 0.65 and 0.70.
- Out-of-scope questions are easier to separate with dense cosine thresholds. At `DENSE_SCORE_GE_0.70` and stricter, the out-of-scope abstain rate was 1.0000.
- Hybrid RRF margin is not a reliable standalone abstention signal in this calibration output because many unsupported queries had margins comparable to supported queries.
- Multiple-chunk support is useful as a diagnostic but insufficient by itself because unsupported queries can still concentrate retrieval evidence around the same incorrect document.

## Conclusion

This run completed the approved abstention calibration without changing the retrieval architecture, corpus, thresholds, candidate rules, HANA tables, or production application behavior.

The most promising candidate families appear to be dense-score thresholds and dense-score thresholds combined with agreement or chunk-support diagnostics. `DENSE_SCORE_GE_0.75` provides the cleanest unsupported abstention behavior in this calibration set but sacrifices substantial safe-answer recall and coverage. `DENSE_SCORE_GE_0.70` keeps much higher safe-answer recall but still accepts several near-domain unsupported queries.

No production abstention threshold is selected here. Final selection requires project review and later validation on a fresh held-out set before any production abstention behavior is implemented.
